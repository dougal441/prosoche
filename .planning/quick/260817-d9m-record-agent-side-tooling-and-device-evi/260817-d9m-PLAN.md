<scope_decisions>
Three scope questions were put to this plan. All three are decided here, explicitly.

**1. `docs/BUILD-NOTES.md` §3 — YES, and larger than first scoped.**
§3 carries the **binding citation rule**: an Evidence cell "that does not name at least one of the
five ToolKit JSON files, one of the prose reference docs, or one golden-shortcut XML filename **is
not acceptable**." As written, that rule admits no simulator or probe observation at all — a future
agent who runs one has no legal way to cite it, so the finding is either dropped or laundered into a
file-level citation it did not come from. That is a functional gap in BUILD-NOTES, not a redundancy
with CLAUDE.md. The recording duty added by this amendment makes the case stronger: a duty to record
belongs in the evidence protocol, next to the rule it qualifies. Task 3 does both, in ≤20 lines,
restating no measured fact so nothing can drift.

**2. `docs/CAPABILITY-DECISIONS.md` — NO EDIT.**
Its 498 lines are a ledger of settled `BD-NN` decision records; it contains no protocol or
how-to-record section, so a rule about recording has no natural home there. And there is no probe
result yet to record — creating a placeholder BD entry with nothing in it would violate the
project's own do-not-fabricate posture. §9 and BUILD-NOTES §3 both **name** it as the destination for
a probe result that settles a capability question; the file itself is touched when there is a real
result, by the task that produces it.

**3. The `### Evidence hierarchy` under `## Conventions` — NOT AMENDED, cross-referenced instead.**
That four-item list (donor > golden corpus > ToolKit catalog > inference) ranks donors first and
names neither probes nor the simulator, so it is in tension with the new ladder. It lives in a
*different* managed block, sourced from `.planning/spikes/CONVENTIONS.md` — amending it means a
fourth file and a second generator source to keep in sync, for a tension one cross-reference line
resolves. So §9's ladder states plainly that it extends that list and supplies the rungs it omits.
If the user later wants the hierarchy itself rewritten, the source path is recorded above.
</scope_decisions>
