<objective>
Prove — or disprove, with equally clear evidence — that the capture-and-restore mechanism this
experimental fork ships (Dimming/Silence, fixed by `09-01-PLAN.md`) is actually safe on a real
iPhone under ordinary use and under force-quit, restart, missed-CLOSE, and overlapping-session
failure modes. This plan is entirely device-dependent: this session confirmed zero connected
iPhones (`xcrun devicectl`), so every task below either produces the artifacts a human needs to run
the trial (Task 1, autonomous) or is a `checkpoint:human-verify` the human completes on their own
device and reports back (Tasks 2-3). No task in this plan can be marked complete by static analysis
alone.

No SPEC.md exists for this phase; per the specless-probe fallback, no automated edge/prohibition
probes are generated this run. `must_haves.truths` above are lifted directly from ROADMAP.md Phase
9's success criteria 2 through 7 — the phase's own de facto spec in SPEC.md's absence. This plan
owns the RESTORE-02 through RESTORE-07 requirement IDs proposed during this planning pass (RESTORE-01,
the static generator fix, belongs to `09-01-PLAN.md`, which this plan depends on).

Purpose: Answer the originating todo's actual question — "does stateful environmental friction work
safely on iOS 26 Shortcuts?" — with device evidence, not a diff. The main-line cut in
`.planning/todos/pending/2026-08-15-ship-readiness-cleanup.md` proceeds independently regardless of
this plan's verdict; this plan produces the evidence that verdict should be judged against.
Output: A freshly signed `.shortcut` for each fork (carrying the 09-01-PLAN.md coercion fix) and a
completed `09-UAT.md` with every test resolved (pass/issue/skipped) and a written `## Verdict`
section.
