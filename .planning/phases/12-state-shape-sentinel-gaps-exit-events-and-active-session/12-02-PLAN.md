<objective>
Establish `active_session` as a **permanent four-leaf container** in the bootstrap
`state.json` template and guard it — the seed half of the container/leaf split, landed on
its own so the emitted plist is unchanged and the build stays green while the shape moves
underneath it.

**Why this is SESS-07 and SAFE-01, not tidiness.** `restore_managed_settings("Reloaded
State")` — the only path that restores brightness and volume after a Dimming or Silence
primitive — is emitted inside three nested `active_session`-derived arms in
`close_pipeline()`: the entry existence gate, the reload existence gate, and the ownership
compare. Every `.id` / `.started_at` / `.declared_duration_seconds` dotted read on that
path currently runs against a bare JSON `null` parent on a fresh state file. A hard
"could not evaluate the key path" error at any of them aborts the run **before** the
restore, leaving the user on a dimmed screen or a silenced device with no restore — which
is precisely the failure `.claude/CLAUDE.md` names when it says capture-and-restore
reliability *is* the safety mechanism.

Purpose: make every `active_session.<leaf>` read structurally incapable of raising, so the
gate conversion in Plan 12-03 has a permanent invariant to gate against.
Output: one seeder, one guard, one re-pointed anchor, two regenerated forks.

Binding constraints D-01..D-04 as stated in `12-01-PLAN.md` `<objective>` apply unchanged
(provenance gate; two-gate validation; never fabricate; exact display names Core / Aware).
</objective>
