**`## Field reference`** — a table with these five columns: `Key path`, `Value`, `Meaning`, `Provenance`, `Tunable range`. One row per leaf key in the literal, using dotted key paths such as `heat.decay_interval_seconds` and `thresholds.Limbo`.

The `Provenance` cell is the discipline that matters. It holds either a canonical section reference (`§10.2`, `§10.3`, `§10.5`, `§12`, `§21`, `§22`, `§10.1`, `§10.4`) or the literal string `PROTOTYPE DEFAULT` when the value had to be chosen because canonical strategy specifies none, or `PROTOTYPE INTERPRETATION` when canonical strategy states a rule but leaves its resolution open. Apply it honestly:

- `thresholds.*`, `cooldown_seconds.*`, `sequences.*`, `gravity.*`, `behavioural_day.offset_seconds`, `heat.open_base`, `heat.reopen_under_120s_bonus`, `heat.reopen_under_600s_bonus`, `heat.overrun_penalty`, `heat.overrun_ratio`, `heat.overrun_min_seconds`, `heat.contract_respected_relief`, `heat.decay_amount`, `heat.decay_interval_seconds`, `heat.floor`, `heat.cap`, `safety.brightness_floor`, `safety.dim_target`, `safety.allow_volume_increase` all carry a canonical section reference.
- `exits.exploration_rate`, `exits.exploit_min_observations`, `heat.ice_expiry_relief`, and `config_version` carry `PROTOTYPE DEFAULT` — canonical strategy requires each of the first three to exist but states no number.
- `heat.reopen_bonus_mode` carries `PROTOTYPE INTERPRETATION`.
- `behavioural_day.key_format` carries a canonical reference to §10.1's "format as date key" plus a note that the pattern is a UTS#35 format string consumed by the Format Date action.

The `Tunable range` cell states a sane bound for a prototype tuner, for example that `heat.cap` must stay above the highest threshold in the most aggressive profile or the top Circles become unreachable, that `safety.brightness_floor` must never be lowered to zero, and that `exits.exploration_rate` is a probability between 0 and 1.

**`## Derived-value rules`** — the values that are computed rather than stored, written precisely enough that Phase 3 implements them without reinterpreting canonical strategy:

The behavioural day: take the current instant as a raw Date value, adjust it by `behavioural_day.offset_seconds` using an explicit Subtract operation, then format the adjusted value with `behavioural_day.key_format` to produce the day key. Never do string-level date math. State that this yields an approximate 04:00-to-03:59 day and that its purpose is to close the midnight loophole.

Gravity: the floor of the day's open count divided by `gravity.opens_per_point`, capped at `gravity.cap`. State that the division must be floored to an integer and that the operand must pass through a Number action first, because a JSON-sourced value arrives as dictionary text.

Pressure: Heat plus Gravity.

Circle resolution: the highest index from 1 to 9 whose threshold in the active profile's array is met or exceeded by Pressure, clamped to 1 through 9. Implemented as a bounded nine-iteration scan that overwrites a Circle variable whenever the threshold is satisfied, which lands on the highest satisfied threshold because the arrays ascend. State explicitly that equality tests must not be used, because Shortcuts has no numeric-equals condition code and condition code 0 means "is less than".

The Heat pipeline, as an ordered list, because order changes the result: decay first by `heat.decay_amount` per `heat.decay_interval_seconds` of elapsed time since the last genuine target-app interaction; then add `heat.open_base` for the new OPEN; then add the rapid-reopen bonus subject to `heat.reopen_bonus_mode`; then add `heat.overrun_penalty` if the previous session exceeded its declared duration by more than `heat.overrun_ratio` and by more than `heat.overrun_min_seconds`; then apply `heat.contract_respected_relief` if the previous boundary was respected; then clamp to `heat.floor` and `heat.cap` last. State that the clamp is always last.

State plainly that none of these computations may be delegated to the model, per D-04.

**`## How to use this file`** — expand what plan 01-01 wrote with the concrete transcription recipe. The literal is transcribed into a single Shortcuts Text action and parsed once per run via Detect Dictionary into a variable named `Config`. Values are read with Get Dictionary Value using 1-based dot notation on the key path, for example `thresholds.Limbo` and `heat.cap`. Record the two coercion hazards a Phase 2 or Phase 3 executor will otherwise hit: `safety.allow_volume_increase` is a JSON boolean and will read back as numeric 1 or 0 rather than the strings true or false, so branch on the number; and any value destined for an If comparison must pass through a Text action first, because a Dictionary Value compared directly inside an If can evaluate blank. State that this file is product configuration, never written to `state.json` (per D-02), and that it is authored once and copied verbatim into both the Dumb and the Sentient fork, never hand-diverged.

**`## Change log`** — one dated entry recording that this file was created in Phase 1, naming the plans that wrote it, and stating the rule that any later edit adds a line here.
