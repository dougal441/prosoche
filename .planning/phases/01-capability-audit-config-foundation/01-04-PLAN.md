## Decision legend (source: `01-CONTEXT.md`)

- **D-01** — Target iOS 26.x, native Shortcuts only.
- **D-07** — The "do not fabricate" protocol: safest fallback, record the deviation, keep the Shortcut runnable. UNVERIFIED is a correct outcome; an invented identifier is a defect.
- **D-09** — Blocker 2, Brightness read-back: only the write action appears to exist. Since section 21 forbids any stateful change that cannot be restored, decide Dimming's degraded form. Check whether `Get Device Details` exposes a usable brightness property before concluding.
- **D-10** — Blocker 3, Volume read-back: same treatment for Silence.
- **D-12** — Also confirm the Notes actions (Create Note, Append to Note, find/show a Note) resolve for the iOS target — the bundled catalog tags them macOS-only, which is likely a snapshot gap, but the whole Control Room onboarding depends on them.

<objective>
Resolve three of the five blockers: whether the Notes actions the Control Room is built on resolve for iOS (per D-12), and whether brightness and volume can be read back before being written (per D-09 and D-10).

Each of the three ends in a written decision, not a deferral. Where a read path cannot be established, canonical strategy section 21 is absolute — a stateful environmental change that cannot be restored must not be made — so the decision records the primitive's degraded, non-stateful form rather than a way to make the change anyway.

Purpose: Phase 2's entire onboarding path depends on Notes. Phase 5's Silence and Dimming primitives, Phase 4's CLOSE restoration step, and Emergency Restore all depend on knowing today whether an original value can be captured. Deciding this here is what stops Phase 5 from discovering it mid-build.

Output: eight more capability rows and their deviation entries in `docs/BUILD-NOTES.md`, at least one user action item, and BD-02, BD-03 and BD-05 written in full in `docs/CAPABILITY-DECISIONS.md`.
</objective>
