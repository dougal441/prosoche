<objective>
Give gate A a waiver that is executable rather than remembered.

The identifier this phase ships is genuinely absent from all three bundled ToolKit snapshots.
Measured: the validator emits two error lines per instance for a descriptor-less unknown
identifier, and offers no allowlist, no ignore flag, no waiver file and no environment override.
So **gate A can never exit zero again**, and the project's own instructions currently demand
that it does — while the same document forbids chaining a permanently-failing gate into a
definition of done. Both cannot stand.

The resolution is the one gate B already models: state the invocation, state the expected exit
status, carry a waiver table with one row per permitted line family, and make the waiver
**mechanical**. Anything the validator reports outside that waiver is a real finding.

Purpose: gate A is the identifier and availability baseline every plan, todo and checker in this
project names. The amendment must be narrow, mechanical, and loud when the residue changes in
**either** direction.

Output: an amended constitutional clause, a checker that makes the waiver executable, and a
deviation entry that reaches a future reader before they reach for the wrong identifier.
</objective>
