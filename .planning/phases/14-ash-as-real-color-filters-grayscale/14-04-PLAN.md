<objective>
Discharge locked decision **D-14-01**: the project's gate-A rule cannot survive contact with an
identifier that is real on the device and absent from every bundled catalog, so the rule is
amended and the waiver is made mechanical.

**Measured, not inferred.** The validator emits its complaint once per instance for this
identifier, and it has **no allowlist, no waiver flag, no environment variable and no
repo-controllable data path** — it accepts exactly two options beyond the file path, and it
builds its identifier set from data files resolved relative to its own script inside the plugin
cache. Signing is unaffected: a signed artifact was produced from a plist carrying the unknown
identifier with no descriptor at all. **The artifact remains shippable; what changes is the
project's own definition of gate A.**

**The alternatives were considered and rejected on the record.** Synthesising a descriptor does
not make the gate clean and fabricates three values no donor supplies. Vendoring a patched
catalog has no override path and is lost on the next plugin update. Substituting the macOS twin
buys a green check by shipping an action that does nothing on an iPhone.

Purpose: gate A is the identifier and availability baseline that every plan, every pending todo
and every checker in this project names. Amending it carelessly would blunt it for everything
else; leaving it unamended would mean every plan in this phase chains a permanently-failing gate
into its definition of done, which the same document forbids. The amendment must therefore be
**narrow, mechanical, and loud when the expected residue changes in either direction**.

Output: an amended constitutional clause, a new checker that makes the waiver executable, and a
deviation-log entry that reaches a future reader before they reach for the wrong identifier.
</objective>
