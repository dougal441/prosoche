<objective>
Normalise `voice_enabled` to the JSON numbers `1` and `0` at the bootstrap writer so both writers of
that key agree, bump `schema_version` 4 → 5 so an existing file carrying the old boolean form is
rebuilt once, and add a build guard that holds both properties.

Purpose: `voice_enabled` is the gate CIRC-08 hangs on, and it is currently written with **two
different JSON types by two different writers** — bootstrap emits the unquoted boolean
`true`/`false`, while Control Room → Toggle Voice emits the number `1`/`0`. Both readers coerce
through `WFNumberContentItem` and compare `> 0`, and `.claude/CLAUDE.md`'s device-verified
runtime-semantics table covers only `"null"` and `""`; **boolean coercion is explicitly unaudited
(axis 6)**. If `"true"` coerces to nothing, The Voice is silent on every fresh install that answered
*yes*, and CIRC-08 is unsatisfiable no matter how well the primitive is written. D-05 resolves this
by making the question moot rather than by spending a device session answering it.
Output: one type at the key, one shape at every reader, and a guard that fails the build if either
slips.

**Standing constraints carried from plan 15-01, restated so an executor does not "fix" them:**
`docs/manifest_check.py` is **expected red** from the moment either fork was rebuilt in wave 1 and
stays red until plan 15-05 re-signs both forks and re-derives the MANIFEST rows — do not edit
MANIFEST rows without re-signing. And CIRC-08 remains **device-unproven** until plan 15-02's
verdict says otherwise; nothing here changes that.
</objective>
