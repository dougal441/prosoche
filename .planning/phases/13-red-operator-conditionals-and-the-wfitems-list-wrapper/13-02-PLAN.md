<objective>
Pin a shape that is already correct, and stop the record from asserting otherwise.

**The ROADMAP is wrong about this family and the research settled it.**
`.planning/debug/Donor 5.shortcut` was decrypted for the first time during research and it
contains exactly the construct the ROADMAP suspected of being a defect: a variable placed into
a conditional's TEXT-slot operand as a `WFTextTokenString` template — `string` holding a single
`U+FFFC`, `attachmentsByRange` keyed `{0, 1}` holding a **bare** `{Type: "Variable",
VariableName: …}` dict — alongside a `WFInput` taking the *opposite* `WFTextTokenAttachment`
envelope, with **no** coercion aggrandizement on either side and `WFCondition` as an integer.
That donor was authored by iOS itself on the target iPhone, which puts it at the top of this
project's evidence hierarchy. `token()` at `tools/build_state_engine.py:145-148` emits a
key-for-key identical shape.

**Therefore there is no sweep to perform.** Measured at HEAD and re-measured during planning:
0 defective sites, not 14. Each fork carries 192 (Core) / 195 (Aware) mode-0 conditionals with a
`WFConditionalActionString`; exactly 20 of them are variable-bearing, split 19 at `WFCondition` 4
and 1 at 99; all 20 match Donor 5; and there are 0 bare abandoned placeholders (the variant the
existing guard already blocks). Sweeping would replace a device-confirmed shape with a guess,
which the project's do-not-fabricate rule forbids outright. The site the ROADMAP named as a
starting point, `if_block("Previous Respected", 4, ...)`, is not even a member of the family —
it passes a raw Python literal, never a `token()`.

**So the deliverable inverts: pin, do not fix.** The standing risk is not that the shape is
wrong, it is that the ROADMAP, the pending todo and `HANDOFF.md` all still assert it is wrong,
so a future pass "fixes" 20 correct sites. The countermeasure is a positive assertion inside the
guard that already owns this slot, plus provenance in its docstring so the refutation travels
with the code. Plan 13-03 does the same job for the prose record.

**Why this is CIRC-07 work, not bookkeeping.** The variable-bearing conditionals include the
fact gates that select the Mirror's success-versus-lapse template family. A pass that broke the
`token()` envelope would leave those comparisons unable to match a real value, and the Mirror
would silently fall through to the wrong template — the same "built only from recorded facts"
guarantee CIRC-07 makes, failing in a different way from plan 13-01's blank rows.

**The masking trap, named in advance.** `verify_conditional_action_string()` will carry two
`raise` statements after this plan. The first short-circuits the second. Plan 12-03 hit exactly
this and solved it with a direct-call isolation script; Task 2 pre-specifies that path rather
than discovering it mid-execution.

**Binding constraints.** D-01 (build provenance ancestor check before either generator),
D-02 (gate A mandatory and clean; gate B advisory, not run here, never `&&`-chained),
D-03 (never fabricate a parameter shape) and D-04 (`docs/manifest_check.py` is expected red
until plan 13-04 re-signs) apply unchanged from `13-01-PLAN.md` `<objective>`.
