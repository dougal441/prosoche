<objective>
Fix the one real defect family in this phase, end to end, on its own commit.

**What is actually broken.** Every `is.workflow.actions.list` action emitted by `mirror_text()`
places raw `WFTextTokenString` dicts directly into `WFItems`. Donors 4 and 4.1 — decrypted
device-authored shortcuts, the top of this project's evidence hierarchy — show iOS itself
wrapping a variable-bearing row as `{"WFItemType": 0, "WFValue": <WFTextTokenString>}` and
leaving a literal row as a bare string. An unwrapped row validates, signs and imports, then
renders as an **empty row** on device, so the Mirror can select a blank template — exactly the
failure CIRC-07 forbids, and invisible to the validator, to the ToolKit catalog (which has no
entry for `WFItems` row shape at all), and to decrypting the signed artifact.

**Scale, measured, not assumed.** The ROADMAP records "2 confirmed instances". Direct
`plistlib` measurement of both artifacts at HEAD, re-run during planning, finds **66 defective
List actions carrying 660 unwrapped rows in each fork** — 33× more actions and 330× more rows.
All 66 come from one function. The fix is one branch in one emitter.

**The load-bearing nuance.** `list_items()` at `tools/build_state_engine.py:416-419` emits the
byte-identical `WFItems=list(items)` expression and is **correct** — its callers pass plain
strings. The emitter cannot tell the two apart; only the row value's Python type can. A blanket
sweep of the `WFItems=` expression would corrupt `list_items(EXIT_NAMES, ...)`'s six literal
rows. Branch per row.

**Why this is the tracer.** It is the thinnest path that touches every layer this phase
modifies — emitter helper, guard, Dumb harness registration, per-fork arming in the Aware
generator, both built artifacts, validator gate A — wired end to end and verified end to end
before any expansion task. If the architecture is wrong, it is wrong after one commit rather
than after four.

**Regression-protection requirements, stated rather than invented.** CIRC-04 (Confession) and
ROOM-03 (the Note's Automation B steps) have **no defect site in this family**. They are
carried by this plan as regression-protection only: `docs/phase5_self_check.py` and
`docs/note_identity_check.py` must stay green through the rebuild. No task in this plan
"addresses" them by changing anything.
