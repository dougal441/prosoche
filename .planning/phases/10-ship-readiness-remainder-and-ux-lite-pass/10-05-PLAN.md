  <action>
Write a self-contained UAT document matching the shape of the Phase 9 UAT file: a header block, then
one numbered test per row, each carrying a setup, an exact tap or trigger sequence, the exact
expected observation, the exact evidence to capture on failure, and an outcome field left blank.

The header records: the phase, the date, the SHA-256 and byte size of the signed Dumb artifact under
test as recorded in the refreshed manifest, the device requirement (an iPhone on iOS 26.x with both
Personal Automations already built and pointing at the Dumb fork by its display name), and a plain
statement that every test in this file is blocked on DIST-03 while no device is connected.

Include a first, separate re-import step, not a test: the device must import the newly signed
artifact, replacing the existing library entry by name, before any test runs — otherwise every
observation describes the previous build. State that `state.json` and the Control Room Note survive
a re-import, so no state is lost and no test needs a fresh install.

Then these tests, one row each:

1. Silent band, first open of a behavioural day. With state reset for today via the manual menu's
Reset Today, open a tracked app once. Expect nothing at all: no banner, no menu, no alert. Then open
the manual menu and choose Status; expect Pressure and the open count to have moved and the Circle
line to read zero with its silent-band gloss. This is the phase's headline claim and its most
important single test.

2. Band exit. Keep reopening the tracked app until Pressure crosses the active profile's entry
threshold — for the default Limbo profile that is a Pressure of 3. Expect the Leaving and Continue
menu to appear for the first time at that open, carrying the reworded prompt, followed by the
Circle-1 primitive. Record how many opens it took, because that number is the tuning signal the
raised thresholds exist to produce.

3. No OPEN notification. Across every open in tests 1 and 2, expect no Circle-and-pressure-and-heat
banner at any point. If one appears, capture a screenshot of it.

4. Control Room note-show, positive leg. From the manual menu choose Open Control Room. Expect the
Control Room Note to open directly in the Notes app with no intermediate note-list picker. This is
the cycle-16 filter-notes fix's behavioural confirmation, which is the specific device item the
ROADMAP names for this phase; its plist-level fix is already applied and Donor-8-matched, so only
the effect is unverified.

5. Control Room note-show, negative leg. From the manual menu choose Status, then Toggle Voice, then
Reset Today, each as a separate run. Expect the Notes app not to open on any of the three. This is
the regression check for the new gate and is at least as important as test 4.

6. Setup Check on a device where both automations work. Choose Setup Check. Expect both automations
reported as seen. Then, on a device where Automation B has never fired, expect Automation A seen and
Automation B not seen. Record which of the two situations the device is actually in rather than
forcing both.

7. Manual menu prompt. Trigger the manual menu and read its prompt. Expect it to state that this is
manual control, that it also opens when an automation passed an unrecognised input, and to point at
Open Control Room. Judgement test: record whether it reads as an explanation to a person who did not
expect it.

8. The menu-on-close report. Trigger Automation B by closing a tracked app. Expect no menu. If a menu
does appear, this is the diagnostic that settles it: capture a screenshot of Automation B's Run
Shortcut action showing its input field verbatim, including any trailing whitespace or autocorrect
substitution. The CLOSE arm provably contains no menu, so a menu here means the input did not match
the expected literal and the run fell through to manual control by design.

9. Dimming and Silence capture and restore, abbreviated. Use Test a Circle to fire the Dimming Circle
and then the Silence Circle, and confirm the device returns to its original brightness and volume
afterwards. This is not a substitute for the Phase 9 UAT's twelve tests, which remain outstanding and
own the failure-mode trials — say so explicitly and link that file. It is here only because this
phase re-signed the artifact those tests were written against, so a smoke check that the path still
behaves belongs with this build.

10. Emergency Restore. From the manual menu choose Emergency Restore while a Dimming or Silence
change is outstanding. Expect brightness and volume to return to their originals and any cool-down to
clear. This is SAFE-05's behavioural confirmation.

Close the file with a results table with one row per test and an outcome column, plus a standing
note in the same wording the breadcrumb-strip quick task used: if no device is available, record the
blocker, leave every outcome blank, and do not substitute a Mac import, a simulator run, or any
inference from the decrypted artifact for a device observation. The decrypted-artifact evidence from
10-04 proves structure, never behaviour, and the difference is the entire reason this file exists.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Signed artifact -> the user's iPhone | Import replaces the library entry by display name. A name mismatch leaves the old build running while the new one sits unreferenced |
| iOS Personal Automation -> Shortcut Input | The input literal is configured by hand on the device and is not in the repository. Test 8's diagnostic exists precisely because this boundary is invisible to every check the repository can run |
| The device -> the project record | The realistic threat here is a criterion marked passed on evidence that never came from a device |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-10-28 | Repudiation | A device criterion marked passed on non-device evidence | high | mitigate | Structural evidence from the decrypted artifact proves what the file contains, never what iOS does with it — the project's own record states that operator and operand type validity and interactive-fallback behaviour are invisible to every file-level channel. The checkpoint's `blocked` path is explicit, the UAT's closing note forbids the substitution by name, and every outcome field starts blank |
