16-05. The reason is measured rather than stylistic: the site class was undercounted **four times**

loop. A safety-critical code fix must not be held hostage to a documentation sweep with that record.

**What this plan owns is six CODE sites**, enumerated with measured anchors in
`must_haves.truths`. One of them, `docs/phase5_self_check.py:117`, is the finding that ended the
enumeration loop: it encodes the retired rule as a **value check carrying none of the vocabulary**,
so a repo-wide grep over that file returns zero matches while the site is live. Plan 16-05's gate
cannot see it. It is fixed here, by hand, because only a human-reasoned read reaches it.

**One CODE site is not documentation - it ships.** `dimming()` emits a Shortcuts `comment()`

instruction reaches it.

The safety property is unchanged and is the whole point of the phase: **capture-and-restore
reliability**, not floor avoidance. Plan 16-01 made that property real for the first time by
persisting the capture; this plan is only safe to land after it, which is why it is wave 2.

| Boundary | Description |
|----------|-------------|
| Config literal (build time) → shipped runtime behaviour | A number in the Config literal becomes a physical change to the user's display with no runtime validation between the two. |
| checker assertion → that checker's own prose about the assertion | A description that outlives the assertion it describes is a live false statement inside the guard. |
| iOS device state → shortcut run | Unchanged from 16-01: `Get Device Details` remains the untrusted external reading. |
