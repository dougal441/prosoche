<objective>
Close the guard that could not fail, give the phase's only critical threat a standing checker,
raise a floor that had no teeth, and put the interim record where the phase's own prohibition
requires.

`verify_panic_escape_seed()`'s third assertion matches conditionals by a bare variable-name
literal that exists nowhere as a shared constant — the emitter carries its own copy forty lines
away. Re-confirmed against HEAD `e6b96e3` in this session: `tools/build_state_engine.py:3305`
still tests `name == "Panic Escape Enabled"`. The original review ran the precise negative
control: rename only the emitter's variable and flip its gate to the exact existence test the
guard forbids, leave the guard's literal untouched, and the build exits 0 with all checkers
green. The guard is vacuous under exactly the drift it exists to catch, and it does not cover the
two gates in `panic_escape_branch()` that decide whether the flag is written at all (re-confirmed
this session at `:2344` and `:2372`, both still numeric today but neither one asserted by the
guard).

The phase's only `critical` threat, T-11-22 (Emergency Restore must never be enclosed by a Panic
Escape conditional), still has **no standing checker** — confirmed this session by grepping
`tools/*.py` and `docs/*.py` for `verify_panic_escape_isolation`, which returns nothing. Its
verification remains the hand-measurement recorded in `MANIFEST.md` prose that the original
review flagged (WR-15): real, correct today, and un-re-run by the next change to
`universal_leaving()` or `panic_escape_branch()`.

**One item from the original review is already closed, independently of this plan, and this
plan records that rather than re-doing the work.** WR-03 flagged
`docs/phase5_self_check.py`'s brightness assertion as unsatisfiable — a scalar comparison against
an operand that is always a variable descriptor by construction. Re-read this session: Phase 16
(plans 16-02 and 16-03) already replaced it. The current assertion (`:148-151`) tests
`"WFBrightness" in params` — operand *presence*, not a numeric band — with a docstring citing
CAP-08's own device-measured finding that an ABSENT `WFBrightness` silently applies an unrequested
default rather than raising an error. This is a different, better-evidenced fix than the one this
plan originally proposed (which would have tested for a variable descriptor rather than a
literal), and it closes the same finding. This plan does not touch that assertion again; touching
a guard that already tests something real, to make it test something else that was never wrong,
would be exactly the kind of guard-for-guard's-sake churn the project's own conventions warn
against.

The token-string floor sits below the measured value on both forks, leaving real slack on the
axis-2 defect it names. And the phase prohibited presenting an interim stand-in as designed
behaviour, requiring each to be named in the generator **and** in `docs/BUILD-NOTES.md` with its
replacing phase. Both are recorded — in the generator and in the config block. Neither is in the
file the prohibition names, confirmed this session (`grep -c 'Eject' docs/BUILD-NOTES.md` returns
0; `Loud Mirror` appears only inside an evidence-table count).

Purpose: leave behind guards that fail on the defects they name, give the phase's one critical
threat a standing check, and leave a record where it was asked to be.
Output: one guard resolved by provenance and extended to all three gates, a new isolation guard
for T-11-22, a raised token-string floor, an explicit record that the brightness-operand item is
already closed, and two interim records in the required file.
</objective>
