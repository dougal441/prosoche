<objective>
Two of the nine shipped interventions do nothing, and this phase advertised them as working.

`dimming()` and `silence()` read the `settings_snapshot.<x>` **container** and gate it on
"has any value", with the entire capture-and-apply body — the device read, the three snapshot
writes, the environmental write, and even the "could not be captured, so nothing was changed"
fallback alert — in the arm that is taken when the container is absent. But `clear_snapshot()`
clears the leaf and never the container, and its own docstring calls the container a permanent
bootstrap invariant. The gate is therefore permanently true, both primitives take the `Nothing`
arm on every run, and 44 environmental actions per fork are unreachable — measured, not
inferred.

The fix is small and already written elsewhere in the same file:
`restore_managed_settings()` gates the leaf numerically and puts its work in the reachable arm.

Purpose: make two of BD-06's nine interventions actually intervene, and make the dead-arm shape
a build failure rather than something a site table can certify.
Output: two re-gated primitives, one new build guard armed in both builders, corrected numbers
and corrected prose in every place the false claim is asserted.
</objective>

<scope_judgment>
## This gap is closed here, not deferred to Phase 16 — and here is the reasoning against the safety argument

**The safety argument, stated fairly and not strawmanned.** Phase 16 owns "Dimming and Silence
as distinct device-proven Circles". Making these bodies live changes real device behaviour:
brightness and volume writes that have been inert begin firing. DIST-03 is open, so no device
can confirm the capture-and-restore loop. `09-UAT.md` has twelve tests and eleven have never
run. `.claude/CLAUDE.md` states that capture-and-restore reliability *is* the safety mechanism,
not floor avoidance. Every one of those is true and none is disputed below.

**Four reasons it is still closed here.**

1. **The guard cannot be armed otherwise.** The verifier's own second `missing:` item is a build
   guard forbidding this shape. It cannot be armed while the two live sites violate it, unless it
   ships with an exemption set naming them — which is exactly the `KNOWN_ORPHANS` pattern this
   phase emptied and abolished one plan earlier, and exactly the WR-01 shape the verifier called
   theatre. A guard authored today and armed in Phase 16 is a guard that does not exist today.
   "Fix the prose, defer the code" therefore collapses: it leaves the phase shipping a corrected
   claim with no mechanism preventing the next regression.

2. **Deferring hands Phase 16 a dead probe and burns the scarcest input.** Phase 16 is a *device*
   phase — it runs `09-UAT.md` tests 2 through 12 on real hardware. If the gate is still inverted
   when that session happens, every one of those tests observes "nothing happened", the session
   teaches nothing about capture or restore, and Phase 16 must become a generator-fix phase, then
   re-sign, re-import and re-run. `.claude/CLAUDE.md` §9 names the user's time as the scarcest
   input in the project and makes it a standing policy that a probe is tested at the lowest rung
   before it reaches the iPhone: "A probe that fails on import, or fails for a reason unrelated
   to the question it was built to answer, burns a device round trip and teaches nothing." The
   signed artifact *is* the probe Phase 16 will run. Handing it over with the path under test
   unreachable is the defect that policy exists to prevent.

3. **This is not new behaviour; it is the behaviour already decided and twice reaffirmed.**
   BD-02 and BD-03 specify stateful capture-and-restore with a per-run degrade-to-message-only
   branch — which is precisely what the dead body implements, fallback alert included.
   `docs/environmental_restore_check.py`'s entire docstring exists because the proposal to *cut*
   these primitives was cancelled by user decision on 2026-08-16 and reaffirmed on 2026-08-17:
   "Dimming and Silence stay, each as its own distinct Circle, **each with a working
   capture-and-restore loop**." Leaving them inert is closer to quietly executing the cancelled
   cut than fixing them is to overreaching.

4. **Nothing reaches hardware sooner, and the recovery path is structurally proven.** DIST-03
   remains the gate on any device seeing either fork; this plan does not touch it. `restore_managed_settings()`
   is invoked from four independent call sites — the owning CLOSE, the live-cooldown redirect,
   Ice expiry, and the manual Emergency Restore — and this phase's verification measured four
   real Emergency Restore surfaces per fork with **zero** enclosed by any Panic-Escape-gated
   group. The failure direction that matters (capture succeeds, restore fails) has four
   independent chances to fire and one unconditional manual hatch.

**What is deferred, explicitly.** The **device proof** of the capture-and-restore loop — that
`Get Device Details` returns a real correctly-typed value, that the original is restored exactly
on CLOSE, and that force-quit, restart, missed CLOSE, overlapping sessions and lock-screen all
restore or leave a safe value — remains **Phase 16**, requirement **DIST-03**, tests 2 through
12 of `09-UAT.md`. That deferral is recorded in `docs/CAPABILITY-DECISIONS.md` by Task 3, not
merely stated here. Nothing in this plan may assert any of it.

**What changes for Phase 16 as a result.** Its UAT now exercises a live loop rather than a dead
one, and its own goal prose — which currently asserts that the Phase 9 merge "made them live" —
is corrected by Task 3, because that assertion was false when written and would otherwise send
Phase 16 looking for a regression that never existed.
</scope_judgment>
