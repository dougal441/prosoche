<objective>
Close the defect that killed the removal half of this phase's headline deliverable, as a class
rather than as two sites.

`is.workflow.actions.text.match` publishes its output under a name this repository guessed at
two sites and got right at a third, forty lines away in another file. The guess produces no
error: the reference simply does not resolve, the section reads empty, the contains test is
false, and the user is shown a confident "nothing was changed" message on a path that was
supposed to remove their bypass. `ACTION_OUTPUT_NAMES` — the table that exists to make exactly
this failure a build error — does not list the identifier, so `verify_output_names()` is blind
to both sites.

This is the tracer for the whole gap-closure set: it is the thinnest change that touches every
layer the remaining three plans will touch — one generator constant, two emission sites, a
rebuild of both forks, the twelve structural checkers, the validator at the project target,
the signer, and the AEA1 decrypt-verify. Proving that path end to end here means the heavier
gate, fork and guard changes that follow are landing on a loop already known to work.

Purpose: make a silent wrong-name failure impossible to reintroduce at any site, present or
future.
Output: one table entry, two corrected sites, an evidenced consumption shape, and both forks
re-signed and decrypt-verified.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hand-authored Note copy → generator regex → removal branch | The user edits a line in an Apple Note by hand; the generator's pattern and literal must still match it. Untrusted, user-editable text crosses into a control-flow decision. |
| Generator emission → signed container → distributor | A wrong output name validates, signs and imports cleanly, so the boundary carries no error signal at all. |
| Simulator observation → recorded verdict | A rung-2 result must never be recorded as a device fact. |
