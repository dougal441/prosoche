## 3. Panic Escape and optional hardening

Allow the user to deliberately remove the existing **Panic Escape**.

The removal path must:

1. require the user to manually edit the Panic Escape setting in the PROSOCHĒ Note;
2. require explicit confirmation that they want the Panic Escape removed;
3. remove the easy behavioural bypass once confirmed.

At the end of the PROSOCHĒ Note, add a short optional instruction explaining that a user who wants another layer of protection can add the **Shortcuts** app itself to their target-app list, so attempts to open Shortcuts to disable or edit the automations are themselves subject to PROSOCHĒ.
